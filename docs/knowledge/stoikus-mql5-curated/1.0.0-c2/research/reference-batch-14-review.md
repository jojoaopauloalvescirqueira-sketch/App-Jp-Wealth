## Conhecimento e aplicação delimitada

Os objetos de Elliott são invólucros de desenho: Wave3 usa três pontos e Wave5 cinco; Degree/Lines e herança não implementam detecção de padrões ou sinal de trading. Formas geométricas também são apenas objetos ancorados em tempo/preço. Não há fundamento para inserir análise de Elliott no Stoikus por causa desta biblioteca [REF, Elliott Tools/Shape Objects, p.PDF4835–4858].

Setas arbitrárias usam código Wingdings e ENUM_ARROW_ANCHOR; subclasses fixas proíbem mudança de código e retornam false por contrato. O exemplo trata esse false explicitamente como proibição, não falha transitória. Para eventual marcador de diagnóstico do Monitor, usar tipo/código explícito e nome único, verificar Create e não associar aparência a operação de compra/venda sem política separada. Esta é proposta, uso atual não verificado [REF, Arrow Objects, p.PDF4859–4876].

Text e Bitmap usam coordenadas tempo/preço; Label, Edit, Button, BmpLabel, RectLabel e SubChart usam posições de tela. Label/SubChart/BmpLabel proíbem Time/Price setters; Edit/RectLabel proíbem Angle setters. Uma camada visual genérica precisa respeitar essas capacidades, evitando repetir chamadas que sempre retornam false [REF, Control Objects, p.PDF4877–4975].

ReadOnly de Edit desabilita edição de texto. State de Button/BmpLabel representa pressionado/solto. Nenhum desses estados constitui autorização para armar Supervisor ou negociar. Proposta: painel informativo pode usar ReadOnly para dados derivados e separar evento gráfico de autorização de domínio; nenhuma implementação foi feita [REF, ReadOnly/State, p.PDF4909,4916,4959].

Getters retornam sentinelas diferentes: 0, false, string vazia, WRONG_VALUE, EMPTY_VALUE ou CLR_NONE. Muitos valores são também estados legítimos; leitura isolada não demonstra que o objeto está anexado. BackColor de RectLabel documenta 0 sem objeto, enquanto Edit documenta CLR_NONE. Save/Load recebem handle aberto (geralmente binário); os exemplos de Arrow fecham o arquivo e verificam bool, mas não demonstram persistência normativa do produto [REF, p.PDF4839–4842,4864–4869,4881–4884,4907–4909,4970].

Offsets de Bitmap/BmpLabel recortam a imagem a partir de pixels do canto superior esquerdo da imagem original; não são deslocamentos de preço. BmpLabel mantém arquivos distintos On/Off. SubChart permite símbolo, período int, escala double e flags de escala de data/preço. São possibilidades de diagnóstico visual, sem uso atual confirmado [REF, p.PDF4920–4964].

A referência contém inconsistências aparentes: tabela Up/Down e thumbs invertida em pontos do texto; BmpFile getter string diz retornar false; introdução Edit diz Gets onde as páginas X_Size/Y_Size mostram setters; nomes CCartObjectBmpLabel/CChartObjectRectangleLabel e pontuação Wave5 variam. Não corrigir produto por isso; conferir headers da versão instalada e compilar exemplo isolado caso venham a ser usados. Aparência não foi inferida [REF, p.PDF4846–4847,4859,4871,4901,4905–4906,4941,4952–4953,4975].

Custom Graphics foi lida apenas na página introdutória4976. Lista Canvas, ChartCanvas e gráficos histograma/linha/pizza; não autoriza conclusão sobre métodos dos capítulos seguintes.

**Exemplos MQL: NOT_RUN. Visual do PDF/objetos: NOT_PERFORMED.** Sem alteração de produto, manual, harness, Git ou instruções.
